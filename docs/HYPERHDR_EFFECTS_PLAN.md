# Эффекты HyperHDR для приложений

## Цель

Добавить для каждого приложения и игры выбор режима подсветки:

- обычный режим захвата экрана;
- конкретный эффект HyperHDR;
- текущее правило AmbiSun `По солнцу`, `Всегда включено` или `Всегда выключено`.

Существующие правила включения не меняются. Эффект определяет только источник цвета в момент, когда правило разрешило подсветку.

## Что уже подтверждено в HyperHDR

Официальный JSON-RPC API HyperHDR поддерживает:

```json
{"command":"serverinfo"}
```

В ответе текущего экземпляра есть массив `effects` с объектами вида `{ "name": "Rainbow swirl" }`.

Запуск эффекта:

```json
{
  "command": "effect",
  "effect": { "name": "Rainbow swirl", "args": {} },
  "priority": 64,
  "duration": -1,
  "origin": "AmbiSun"
}
```

Остановка собственного канала:

```json
{"command":"clear","priority":64}
```

Источник: [официальный HyperAPI.cpp](https://github.com/awawa-dev/HyperHDR/blob/master/sources/api/HyperAPI.cpp) и [формирование serverinfo](https://github.com/awawa-dev/HyperHDR/blob/master/sources/base/HyperHdrInstance.cpp).

## Совместимая модель настроек

Текущие `overrides` со значениями `off`, `sun`, `on` сохраняются без изменений. Добавляется отдельная карта:

```json
{
  "effectOverrides": {
    "game.exe": { "mode": "effect", "name": "Rainbow swirl" },
    "chrome.exe": { "mode": "capture" }
  }
}
```

Отсутствующая запись означает `capture`, поэтому старые настройки продолжают работать после обновления.

Режимы:

- `capture` — обычный захват экрана HyperHDR;
- `effect` — запускается имя, полученное от HyperHDR.

Выключение подсветки по солнечному правилу всегда очищает канал эффекта и выключает LEDDEVICE. При смене приложения сначала очищается канал предыдущего приложения, затем применяется новый режим.

## Обновление списка

1. При подключении к HyperHDR выполнить `serverinfo`.
2. Взять `info.effects`, удалить дубликаты и отсортировать по имени.
3. Показать список в выпадающем поле приложения.
4. Повторять проверку примерно раз в 60 секунд, пока приложение открыто.
5. Добавить ручную кнопку `Обновить эффекты` в настройках HyperHDR.
6. Если HyperHDR недоступен, оставить последний кэш только для отображения и показать предупреждение. Новый эффект запускать только после успешной проверки его наличия.

Список относится к выбранному текущему экземпляру HyperHDR. Поддержку выбора нескольких экземпляров можно добавить отдельно, не меняя формат правил.

## Интерфейс

В строке приложения оставить существующее правило `По солнцу / Всегда включено / Всегда выключено` и добавить компактный список:

- `Захват экрана`;
- список эффектов из HyperHDR.

Для длинного списка используется нативный dropdown, а не раскрытый блок на десятки строк. Эффект `System Shutdown` не показывать в обычном списке: это потенциально опасное системное действие, а не визуальный режим.

Если сохранённый эффект исчез из HyperHDR, строка помечается как недоступная и временно использует `Захват экрана`; пользователь получает понятное предупреждение вместо тихого запуска неправильного режима.

## Порядок реализации

### Windows

1. Добавить Rust-команды `hyperhdr_effects`, `hyperhdr_set_effect`, `hyperhdr_clear_effect` поверх уже существующего RPC.
2. Добавить к конфигурации `effectOverrides` с обратной совместимостью.
3. Изменить Windows automation: вычислять солнечное правило отдельно, затем применять capture/effect.
4. Добавить dropdown и обновление списка в Windows-оверрайде frontend.
5. Проверить запуск, смену приложения, остановку, недоступный эффект и перезапуск HyperHDR.

### webOS

Для webOS потребуется изменение старых общих файлов UI, bridge, конфигурации и сервиса HyperHDR. Это нельзя реализовать только добавлением Windows-модуля. До отдельного разрешения такие файлы не редактируются, чтобы не нарушить рабочую версию webOS.

После разрешения изменения должны быть минимальными и обратными совместимыми: сначала service API и конфигурация, затем bridge и отдельный UI-модуль эффектов.

## Ограничения

- HyperHDR должен быть подключён и иметь запущенный экземпляр.
- Название эффекта хранится как строка HyperHDR, поэтому переименование или удаление эффекта требует повторного выбора.
- Канал `priority` должен принадлежать AmbiSun. Значение по умолчанию — 64, его лучше сделать отдельной расширенной настройкой, если на компьютере есть другие JSON-RPC-клиенты.
- В Microsoft Store функциональность не требует установки драйвера: используется локальный HTTP JSON-RPC и запуск выбранного пользователем HyperHDR. Автозапуск/остановка внешнего процесса нужно явно описать в privacy/capabilities и проверить на сертификационных тестах.
